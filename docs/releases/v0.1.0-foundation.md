# EmotionSense AI v0.1.0 — Foundation

## Release Overview

`v0.1.0-foundation` is the first public repository release of EmotionSense AI. It establishes product, architecture, governance, and Flutter engineering foundations for transparent open-source development. It is not a functional product release and contains no emotion estimation, camera workflow, local history, analytics, backend, or business logic.

The recommended Semantic Versioning tag is `v0.1.0`; `v0.1.0-foundation` is the descriptive GitHub release title and release-note identifier. The mobile package version is `0.1.0+1`, where `+1` is the platform build number.

## Scope

This release provides documentation, community governance, a reproducible Android/iOS Flutter workspace, empty Clean Architecture boundaries, developer tooling, and baseline continuous validation.

## Repository Structure

- `apps/mobile/` — Android/iOS Flutter foundation with no product features.
- `docs/` — requirements, architecture, roadmap, standards, ADRs, planning, and release evidence.
- `ml/` — reserved governed research workspace; no datasets or models are included.
- `packages/` — reserved shared-package workspace.
- `scripts/` — reserved repository automation workspace.
- `docker/` — reserved future container tooling; no backend is present.
- `.github/` — community templates, dependency maintenance, and Flutter validation.

## Engineering Decisions

- Clean Architecture with feature-oriented modules and inward dependencies is the approved style.
- Riverpod and GoRouter provide dependency composition, state, and navigation foundations.
- Repository initialization precedes feature development under [ADR-0002](../DECISIONS/0002-repository-foundation-before-feature-development.md).
- Future user-facing capabilities use progressive enablement when practical under [ADR-0003](../DECISIONS/0003-feature-flags-and-progressive-feature-enablement.md).
- TensorFlow Lite, MediaPipe, and Isar remain approved future technologies but are not dependencies in this release.

## Known Limitations

- The foundation source and annotated `v0.1.0` tag exist; GitHub Release rendering and hosted workflow results must be verified on GitHub.
- The mobile application is a neutral foundation shell, not an implementation of the PRD.
- No model, dataset, camera, microphone, storage, telemetry, authentication, or backend capability is included.
- iOS compilation has not been validated because the available host is Windows.
- Android command-line tooling and license status require local environment remediation.
- A full wireless-device debugger session was interrupted after successful Android installation and launch.
- Hosted GitHub rulesets and security settings, production signing, final application identifiers, and independent security/conduct contacts require repository-owner configuration.

## Validation Summary

- Flutter 3.44.8 stable and Dart 3.12.2 were used.
- Dependency resolution, static analysis, the foundation widget test, and Android debug build passed.
- Internal Markdown links, version declarations, repository naming, ignored artifacts, ADR references, and community configuration were audited for this release.
- Direct dependency versions are recorded in the root README and locked in `apps/mobile/pubspec.lock`.
